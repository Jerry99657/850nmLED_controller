# 850 nm 红外 LED 控制验证板

本项目用于验证 50 颗三芯 5050 850 nm 灯珠（共 150 颗红外 LED 芯片）的恒流驱动、统一调光、5 V/9 V 供电兼容、温度保护与显示交互。

主控为 **ESP32-C3-WROOM-02-N4**。所有红外 LED 同步调光，不支持单灯独立控制。

## 硬件概要

- 红外阵列：15 路恒流串，每路 10 颗 850 nm LED 芯片；共 150 颗。
- LED 驱动：3 × `LP8556SQ-E09`，每颗使用 5 路恒流下拉通道；每路目标电流约 39.4 mA。
- 调光方式：ESP32-C3 输出一组公共 PWM，同时控制三颗 LP8556。
- 功率输入：`HUSB237` USB-C 取电，VSET = 75 kΩ，优先请求 9 V。
- 控制电源：`AP63203` 降压输出 3.3 V。
- 显示与指示：0.96 英寸 SPI TFT、WS2812-V6 状态灯、0805 红色功率随动指示灯。
- 检测：`TMP102` 温度传感器、VBUS 电阻分压采样。

> 5 V 输入可用，但固件必须限制最大 PWM 占空比；9 V 输入才允许满功率运行。

## ESP32-C3 IO 分配

| GPIO | 网络/功能 | 软件外设与说明 |
|---:|---|---|
| GPIO0 | `ADC0`，VBUS 电压采样 | ADC1_CH0；分压比 0.332，5 V 约 1.66 V，9 V 约 3.0 V（超出校准量程，只用于判档） |
| GPIO1 | `LED_PWM` | LEDC PWM；三颗 LP8556 的公共调光输入，同时驱动 0805 红色指示灯 |
| GPIO2 | `KEY_UP` | 低有效按键；启动绑带脚，外部上拉 |
| GPIO3 | `TFT_DC` | SPI 数据/命令选择 |
| GPIO4 | `I2C_SDA` | TMP102；预留 LP8556 I²C 总线 |
| GPIO5 | `I2C_SCL` | I²C 时钟，建议最高 400 kHz |
| GPIO6 | `TFT_SCLK` | SPI 时钟 |
| GPIO7 | `TFT_MOSI` | SPI 数据输出 |
| GPIO8 | `WS2812` | RMT 外设或 SPI 模拟时序；启动绑带脚，外部上拉 |
| GPIO9 | `KEY_DOWN/BOOT` | 低有效按键；复位时按住会进入下载模式 |
| GPIO10 | `TFT_CS` | SPI 片选 |
| GPIO18 | `USB_D-` | 原生 USB Serial/JTAG 下载与日志 |
| GPIO19 | `USB_D+` | 原生 USB Serial/JTAG 下载与日志 |
| GPIO20 | `UART_RXD` | UART 调试/测试点 |
| GPIO21 | `UART_TXD` | UART 调试/测试点 |

`GPIO2`、`GPIO8`、`GPIO9` 为启动绑带脚。按键应接地并依赖外部上拉；GPIO9 不应外接较大电容。

## 外设说明

| 外设 | 接口 | 使用方式 |
|---|---|---|
| LP8556 × 3 | 公共 PWM，I²C 预留 | E09 按 PWM-only 使用；三颗器件 I²C 地址均为 `0x2C`，不可分别读取状态 |
| TMP102 | I²C，地址 `0x48` | 定期读取板上局部温度，用于显示与热保护 |
| 0.96 英寸 TFT | 4 线 SPI | 显示输入电压、亮度、温度、供电模式和故障信息 |
| WS2812-V6 | 单线数据 | 显示初始化、5 V 降额、9 V 正常、预警与故障状态 |
| 0805 红色 LED | GPIO1 公共 PWM | 经 1 kΩ 限流，亮度跟随 PWM 指令，占空比为 0 时熄灭 |
| USB Serial/JTAG | GPIO18/19 | 固件下载、日志输出与调试 |
| UART | GPIO20/21 | 预留外部串口调试与测试点 |

## 计划实现的固件功能

1. 上电后保持 `LED_PWM = 0`，初始化外设并显示系统状态。
2. 采样 VBUS，自动识别 5 V 与 9 V 输入。
3. 两档都允许最大 100% PWM（原计划 5 V 限 50%，现已放开，上限值在 menuconfig “VBUS detection” 里可调）。
4. 使用 LEDC 产生 1～5 kHz 公共 PWM，并使用 300～500 ms 软启动。
5. 读取 TMP102：55 ℃以上预警/降额，65～70 ℃强制降额，70 ℃关断；最终阈值以热测试结果为准。
6. TFT 显示电压、温度、亮度设定值、供电模式及故障信息。
7. 两个按键用于亮度调节；短按步进，长按连续调节。
8. WS2812 显示运行状态：蓝色初始化、绿色 9 V 正常、黄色 5 V 降额、橙色预警、红色故障。
9. 在 VBUS 异常、温度超限或主控复位时立即关闭 PWM。

## 建议开发环境

使用 **VS Code + Espressif IDF 扩展 + ESP-IDF**，Target 选择 `esp32c3`。

推荐先分阶段验证：

1. USB 下载与串口日志。
2. GPIO1 PWM 与 0805 红灯。
3. I²C TMP102。
4. SPI TFT 与按键、WS2812。
5. VBUS ADC 采样与 5 V/9 V 模式切换。
6. 单颗 LP8556 低占空比测试，再逐步接入三组驱动和全部灯串。

当前完成阶段 1~5，并加入手机遥控：

- 操作：KEY_UP 在左、KEY_DOWN 在右，按物理位置使用。左键 = 上一项 / 减小 / 关 / 取消，右键 = 下一项 / 增大 / 开 / 确定，长按连发；两键同时按 = 确定 / 返回。
- 首页：运行、设置、状态、关于。
- 运行页：标题显示 5V/9V 档位，大号显示实际输出，进度条竖线标出当前上限；UP/DOWN 按“调光步进”调设定值。
- VBUS 判档（阶段 5）：每 100 ms 采样，VBUS > 7.5 V 连续 3 次判为 9 V，< 6.5 V 立即判为 5 V；只插下载口、ADC 故障时按 5 V。降档时输出立即压到该档上限，档位变化弹出提示。阈值、回差、分压比、两档上限在 menuconfig “VBUS detection”，目前 5 V / 9 V 上限都是 100%（即不限幅）。
- 上电 `LED_PWM = 0%`，只有在运行页按右键（KEY_DOWN）才会开启；0 → 上限按软启动时间（默认 400 ms）非阻塞爬升。
- TMP102 每 500 ms 读取一次；达到关断阈值（默认 70 ℃，可在板上设置页 / 热点网页 / 手机 App 里改）或连续 3 次读不到时立即关断 PWM 并锁存温度故障。故障状态变化在任意页面弹出提示。
- 过温关断自恢复：关断瞬间记下当时的设定值，温度降到恢复阈值以下，自动按该设定值恢复输出、走软启动斜坡，被暂停的定时接着走。运行页的故障画面直接写出恢复温度。关断时本来就没输出（设定值为 0）则不会自己开起来。温度传感器故障、LED 驱动故障仍是锁定式，要重新按键开启。
- 三个温度阈值（默认 关断 70 / 预警 55 / 恢复 50 ℃）都能在板上设置页改、掉电保存，状态页三行都显示当前值。**预警和恢复只在板子上改**——热点网页和手机 App 只暴露关断温度一个。
- 三档阈值的可调范围**联动**，保证 **恢复 < 预警 < 关断**：每项的范围由另外两项的当前值算出来——恢复 `0 ~ 预警-1`、预警 `恢复+1 ~ 关断-1`、关断 `预警+1 ~ 100`。所以顺序怎么按都设不坏，关断的下限跟着预警走（默认预警 55 → 关断最低 56，在板上把预警调高，网页和 App 里能选的最低关断温度也跟着抬）。范围在 `main/ui_app.c` 的 `cfg_update_ranges()` 里每次改值后重算（`int_bindings` 因此不是 `const`；KK_UI 每次按键都现读 `minimum`/`maximum`，所以运行时改是生效的，vendored 的 `components/kk_ui/` 不用动）。绝对上下限在 `main/control.h` 和 menuconfig "Thermal protection" 里各有一份，改要一起改。
- 关断阈值调低到当前温度以下会立刻关断；恢复阈值调到当前温度以上会立刻解除过温并恢复输出。预警阈值只影响状态灯颜色和状态页文字，不影响输出。
- 设置页：温度保护开关、关断温度、预警温度、恢复温度、软启动时间、调光步进、状态灯开关与亮度、恢复默认；全部掉电保存到 NVS（`main/settings.c`）。
- 温度保护关闭后不再因过温或传感器故障关断，但仍受占空比上限约束；运行页标题显示“保护关闭”。该状态也会保存，上电时为关闭会弹出“温度保护已关闭”提示；“恢复默认”会重新开启。
- WS2812：故障黄色闪烁 > PWM 输出红色（亮度 = 占空比 × 50%）> 温度预警橙色 > 页面颜色（首页蓝、运行绿、设置紫、状态青、关于白）。故障和 PWM 指示不受状态灯开关影响。
- 离开运行页（两键同按返回）时 LED_PWM 立即归零，不走软启动斜坡；其它页面不允许输出。
- 启动时 I²C 先检查 SDA/SCL 空闲电平，再扫描全部地址，TMP102 在 0x48~0x4B 中自动识别。

- LP8556：上电默认 LED_EN（16h）= 0x3F 六路全开，本板只接 5 路。每次检测到 VBUS 上电后，在 PWM 为低（Standby）时写 LED_EN = 0x1F 关闭悬空的 LED6，写入成功前不允许输出；输出中接入功率口会先停止输出再配置，需重新开启。VBUS 有电但持续 2 s 写不进去则锁存“驱动故障”。只插下载口时 LP8556 无供电，不影响 LED52 测试。状态页“LED驱动”显示配置状态。
- 手机遥控：板子开启 WPA2 热点（SSID `850nm-xxxx`，默认密码 `850nm1234`，都显示在“关于”页），手机连接后会自动弹出控制页（强制门户：DNS 全部解析到本机、未知地址重定向、DHCP Option 114）；没有弹出时手动在浏览器打开 `http://192.168.4.1`。系统提示“此网络无法上网”时选择保持连接：

  - 设定占空比（0~100%，超过当前上限会被钳位）；设定 > 0 时板子自动进入运行页。
  - 定时关断（1~999 分钟，输出开启后才能设定）；运行页标题栏显示倒计时，到时自动归零并提示。
  - 关断温度：−/+ 按钮 1 ℃ 步进（`POST /api/temp?c=N`），范围由固件在 `/api/status` 的 `shut_min`/`shut_max` 给出（`shut_min` = 板上预警阈值 + 1，会随板上设置变），连点后停手 250 ms 才发一条。
  - 停止输出；页面每秒刷新输出、上限、VBUS、温度、保护和剩余时间。
  - 停止、故障、离开运行页或定时到时都会同时取消定时；只有过温关断例外，降温恢复后剩余时间接着走。板上按键暂不能设定定时。
  - 上电顺序：先完成屏幕、传感器等小电流外设，Wi-Fi 在后台延时 3 s 启动（上次欠压复位则 9 s），发射功率限制为 10 dBm，欠压复位后自动再降功率，降低 3.3 V DCDC 的瞬态压降。蓝牙在 Wi-Fi 之后再启动（`CONFIG_REMOTE_BLE_ENABLE` 关闭则不启动），进一步错开启动电流。
  - 安全：只有 Wi-Fi 密码一层保护，HTTP 无认证，请在 menuconfig “Wi-Fi remote (phone)” 中修改密码；也可在该菜单关闭遥控。

- 蓝牙控制：与热点同名广播（`850nm-xxxx`）。Android 手机用 Chrome 打开 `tools/ble_control.html`，点“连接板子”选择设备，控制功能与热点网页相同（不含固件更新——那要走热点网页，见下文；状态里还多一行只读的预警温度），手机可同时正常上网。改这个文件后重跑 `python android/build.py` 可同步更新 APK 里的页面。
  - 蓝牙连上后自动关闭热点，断开 3 s 后恢复；有手机连在热点上时停止蓝牙广播。两者都空闲时同时开启，任一方式都能连上。
  - 网页蓝牙需要安全上下文：Android 上从文件管理器打开、地址为 `content://` 时不可用，需放到 HTTPS 网址（如 Gitee Pages）；电脑 Chrome 可直接打开本地文件。iPhone Safari 不支持。
  - 关断温度：−/+ 按钮 1 ℃ 步进，与网页同一套逻辑。状态包字节 [19] 是当前阈值，字节 [18] 的高 7 位是关断下限（= 板上预警阈值 + 1，所以下限跟着板上的设置走，页面不写死）。页面把这 7 位减 1 当**预警温度**只读显示（板上三档温度里，蓝牙只拿得到这一个），保护关闭时页面顶部会单独提示——那种情况下过温不会关断，在这里调关断温度也要等保护重新打开才生效。页面比固件先更新是常态，高位为 0 说明是旧固件（阈值范围当时固定 61~100），退回 `LEGACY_SHUT_MIN` = 61，卡片照常显示，预警温度显示 `--`；只有字节 [19] 也是 0（更早的固件还没有这项功能）才隐藏。
  - 状态包固定 20 字节：手机不主动协商 MTU 时 ATT MTU 是 23，一条 Notify 只能带 23-3 = 20 字节，21 字节的包板子发得出、手机收不到（会被协议栈截掉最后一字节）。连接时那一次 Read 的上限是 22 字节，所以只有 Read 看得出问题、随后的 Notify 就短一截——App 0.3.0 的关断阈值卡片消失就是踩了这个坑。要再加字段得先挤掉一个，或在 App 里 `requestMtu()` 并等 `onMtuChanged` 之后再订阅。
  - 蓝牙未加密，附近任何人都能连接并控制红外输出。可在 menuconfig “Wi-Fi remote (phone)” 关闭。

## 固件在线更新（不用数据线、不进下载模式）

ESP32-C3 没有 STM32 那种 USB DFU，所以“不进下载模式换固件”只有一条路：**OTA**——让板子自己把新镜像写进另一块 app 分区再重启。分区表因此改成双 OTA（`partitions_two_ota_large.csv`，`ota_0`/`ota_1` 各 1700K，见 `sdkconfig.defaults`），NVS 分区偏移和大小与原来的 1500K 单 app 表完全一样（`0x9000`/24K），所以换表不会丢设置。

**第一次要烧一次数据线**：换分区表只能在烧写时做，OTA 改不了分区表。这次必须整片烧写，不能用 `app-flash`：

```text
idf.py -p COMx flash          # 会一并写 0x20000 的 app 和 0xf000 的 ota_data_initial.bin
```

之后更新固件就只用网页，板子、手机、电脑都不用再接数据线：

| 方式 | 怎么用 |
|---|---|
| 板子自带页面 | 连上热点后打开 `http://192.168.4.1`，最下面的“固件更新”卡片选 `build/850nm_led_controller.bin` 上传 |
| 独立更新页 | `tools/fw_update.html`，用本地文件或 http 打开，拖入同一个 `.bin`，填板子地址（默认 `192.168.4.1`） |

细节：

- 只传 `build/850nm_led_controller.bin`（约 1.2 MB，编译产物），不传 bootloader、partition-table、merged 之类的文件。文件大小超过分区会被直接拒掉。
- 板子收完整包、校验通过才换分区，然后重启。**中途失败不影响使用**：还跑原来那版固件，重传一次即可。校验包括 ESP32 镜像头、芯片型号和 `project_name`，所以传错工程的 `.bin` 会被拒（`not_this_board`）而不是刷进去。
- 上传期间别断热点、别让手机切网络。上传途中板子的 HTTP 服务是单任务、被这个请求独占，热点不会关（`ota_busy()` 挡掉了蓝牙连上就关热点的逻辑），强制门户探测会排队等一会儿。
- **更新成功后请让板子通电满 5 秒再断电**：开了 `CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE`，新固件要在启动后 5 秒内证明自己没崩（`app_main.c` 里调 `esp_ota_mark_app_valid_cancel_rollback()`）。这段窗口内断电会被判成“没启动成功”，下次上电自动退回另一个分区——原来的固件还能用，不会变砖，但这次更新白做。启动崩溃的固件同理自动回退。
- 两个分区都坏了（手工烧写也失败）才需要回到数据线恢复，`idf.py -p COMx flash` 就能救回来。
- 版本号在根 `CMakeLists.txt` 的 `PROJECT_VER`，同时显示在板上“关于”页、`/api/status` 的 `ver`/`part` 字段和更新页上；启动日志里会打印当前跑在 `ota_0` 还是 `ota_1`、有没有回过滚。
- 安全：`/api/ota` **没有鉴权**，连上热点（WPA2，密码在“关于”页）的人都能刷固件；这个热点本来也没有别的认证，请勿在有外人的场合开着。可以按下面这条关掉遥控来避免。
- 传错文件、断电、断线都只会导致“这次更新失败”，不会让板子不能用——这是选 OTA 而不是别的方案的主要原因。

menuconfig：PWM 频率/软启动/上限、三个温度阈值（关断 / 预警 / 恢复，都只是**上电默认值**，实际值以 NVS 里保存的为准）、状态灯默认亮度在 "850nm LED Controller"；屏幕参数在 "KK_OLED: ST7735S"。`LED_PWM_DEMO`（阶梯测试）默认关闭，开启后会自动点亮红外阵列。

屏幕调整：驱动工作在面板原生竖屏方向，横屏由软件旋转。启动时先显示 1.5 s 测试图（边框 + 对角线 + 左上角方块 + “160x80”）：

- 边框缺一边或有杂色条 → 调整 `TFT_COL_OFFSET` / `TFT_ROW_OFFSET`（132x162 RAM 面板常见 26/1，128x160 RAM 面板常见 24/0）；
- 画面上下颠倒 → 切换 `TFT_ROTATE_180`（默认已打开，适配当前安装方向）；
- 底色发白、颜色反相 → 关闭 `TFT_INVERT`。

修改 `ui_app.c` 中的界面文字后，需运行 `python tools/gen_ui_fonts.py` 重新生成字模（需联网，只提交字符本身）。

### 不装屏幕（无屏运行）

可以不焊 TFT，把板子当纯遥控 + 热保护板用：

- **屏幕初始化失败会自动降级**：`OLED_Init()` 返回错误时不再初始化 KK_UI，日志打印
  `no LCD/UI: 只保留遥控、热保护、状态灯和 OTA`。此后 Wi-Fi 热点/HTTP 接口、蓝牙、热保护、
  WS2812 状态灯、定时、OTA 全部照常，只是不画图、按键菜单不响应。
- **明确不装屏**就在 menuconfig “850nm LED Controller → Display / UI” 里关掉 `UI_ENABLE`：
  连 1.5 s 测试图和屏幕初始化都省掉，启动更快。
- 无屏时没有“运行页”这个概念，遥控设定占空比直接生效（不再要求先切页面）；反过来说
  **板上两个按键不起作用，只能用 Wi-Fi / 蓝牙控制输出**。
- 保存的设置（关断/预警/恢复温度、软启动、状态灯亮度）与屏幕无关，上电一律读取并生效——
  `ui_app_config_init()` 在 `display_init()` 之前无条件执行。
- 无屏模式下状态灯待机色用运行页的绿色（有屏时按页面变色）。
- 屏幕是后来才装上的，需要重新上电/复位才会初始化。

编译与烧录：在 VS Code 中使用 ESP-IDF 扩展的 Build / Flash / Monitor，或在 IDF PowerShell 中执行 `idf.py -p COMx flash monitor`。想摆脱数据线更新固件见上面“固件在线更新”——换分区表那一次仍然要这样整片烧写一次。

## 安全提示

850 nm 红外输出不适合用肉眼判断亮灭或强度。调试时请使用摄像头、红外探测卡或光功率计确认输出，避免近距离直视发光面；首次通电应从限流电源、低占空比和单驱动测试开始。
